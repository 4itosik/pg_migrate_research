# Задача

## Контекст

- Миграции накатываются [golang-migrate](https://github.com/golang-migrate/migrate) в PostgreSQL.
- Подключение идёт через pgbouncer в transaction mode. Поэтому `search_path` установить нельзя.

## Что нужно

Механизм, который читает SQL-файлы миграций. Если включён флаг и передано имя схемы, он добавляет схему к объектам:

```sql
CREATE TABLE users (...)       -- было
CREATE TABLE auth.users (...)  -- стало
```

Цель этого исследования — найти Go-библиотеку, на которой можно сделать разбор и изменение запросов.

Встраивание в golang-migrate — вне скоупа.

## Уточнённые требования

| Вопрос | Ответ |
|---|---|
| Какие объекты квалифицировать | Таблицы и индексы в DDL; таблицы в DML; прочие объекты (последовательности, типы, представления, функции, триггеры); SQL внутри тел функций и DO-блоков (`$$…$$`) |
| CGO | Только pure Go: сборка с `CGO_ENABLED=0` |
| Результат | Отчёт и PoC на 2–3 библиотеках-кандидатах с общим набором SQL-сценариев |
| Альтернативы без парсинга (regex, `search_path` у роли и т. п.) | Не рассматривать, только библиотеки |
| Версии PostgreSQL | Проверить на PostgreSQL 12, 13, 14, 15, 16 |

## Критерии готовности

1. Отчёт: обзор библиотек, рекомендация, плюсы и минусы кандидатов, ограничения подхода.
2. PoC на 2–3 библиотеках проходят общий корпус миграций на живом PostgreSQL.
3. Корпус и PoC проверены на PostgreSQL 12–16.
