## Этап 0. Основа

Порог: `go test ./...` зелёный в `pgschema/` и в `pgschema/oracle/`, отчёт метрик строится.

Проверено в этой сессии (Go 1.26.1, 4 ядра, linux/amd64):
- `pgschema/`: `go vet` и `go test ./...` с `CGO_ENABLED=0` — зелёные. В модуле пока один тест, `TestDependencies`: в зависимостях только стандартная библиотека.
- `pgschema/oracle/`: `go vet` и `go test ./...` — зелёные.
  - Счёт операторов регрессионных тестов, которые принимает libpg_query, совпал с исследованием на всех версиях: 32 024 / 34 733 / 37 777 / 41 116 / 42 798 (189 / 197 / 206 / 217 / 220 файлов).
  - Корпус: 23 сценария, libpg_query принимает все up- и down-файлы.
  - Прототип на стенде, PostgreSQL 16.15: 22 из 23 (сценарий 12 — динамический SQL, ожидаемое ограничение), `oracle-prototype.json` в `results/pg16/`.
- Контроль корпуса `poc/harness` (`TestBaseline`, `TestNoop`) на PostgreSQL 16.15 зелёный, отчёты — в `results/pgNN/` (эталонные схемы `baseline-schema` не в git, их создаёт `tools/baseline.sh`). `poc/` не менялся.
- Отчёт метрик: `go run ./cmd/metrics`, результат — [results/metrics.json](results/metrics.json) (окружение, корпус, регрессионные тесты по версиям, узлов на оператор). Стадии дополняют его через `oracle.UpdateMetrics`.
- ADR 0001–0005 записаны. Замеры, на которых они стоят: goyacc принимает `gram.y` без конфликтов (6 457 состояний, 5,8 с, таблицы 135 МБ и 4,2 с); дерево `pg_query_go` в 2,8 раза медленнее и в 4 раза тяжелее своих структур, но оператор — 12,5 узла в среднем, поэтому решают позиции имён и зависимости.

Стенд на версиях (прототип через `oracle`, контроль `TestBaseline` и `TestNoop` зелёный на каждой): PostgreSQL 12.22 — 20 из 21 (2 пропущены по `min_server_version`), 13.23 — 21 из 22, 14.24, 15.19 и 16.15 — по 22 из 23. Те же числа, что в исследовании; единственный провал — сценарий 12.

Проверка свежим взглядом: субагент без контекста проверил этап против промпта и прототипа. Блокеров нет. Замечания приняты и исправлены на этапе 1: `migratesrc` — отдельный модуль (ADR 0005), цитаты в ADR 0001 и 0004, воспроизводимость замеров (`tools/probe-goyacc.sh`, `tools/probe-protobuf.sh`, `oracle/treebench_test.go`), лицензии (ADR 0006), в CI тесты сверки падают, а не пропускаются, `cmd/metrics` не затирает разделы, `get-data.sh` не качает `pg_dump` при наличии 16+, метрики сборки (`cmd/buildmetrics`).

## Этап 1. Лексер

Порог: токены и смещения совпадают с `Scan` из libpg_query на всех входах корпуса и регрессионных тестов PostgreSQL 12–16.

Порт `scan.l` (PostgreSQL 17) в `internal/lex`: все виды литералов (`E'…'` со всеми экранированиями и суррогатными парами, `U&'…'`, `$tag$…$tag$`, `B'…'`, `X'…'`, `N'…'`, числа с `_`, `0x`, `0o`, `0b`), вложенные комментарии, продолжение строк через перевод строки, ключевые слова из `kwlist.h` (491, с категориями и признаком `BARE_LABEL`), свёртка и усечение идентификаторов, тексты ошибок и позиции курсора. Таблицы токенов и ключевых слов генерирует `oracle/cmd/gentokens`: номера токенов те же, что у libpg_query.

Сверка (`oracle/lexer_test.go`) сравнивает номер токена, смещения, категорию ключевого слова, а для ошибок — текст сообщения и позицию курсора. Результаты в этой сессии, Go 1.26.1:

| Вход | Всего | Расхождений |
|---|---|---|
| Файлы корпуса, `setup.sql`, `check.sql` | 100 | 0 |
| Операторы регрессионных тестов PostgreSQL 12 / 13 / 14 / 15 / 16 | 32 267 / 35 005 / 38 052 / 41 598 / 43 323 | 0 / 0 / 0 / 0 / 0 |
| Токенов в них на PostgreSQL 16 | 615 286 | |
| Целые файлы регрессионных тестов, в них файлов, которые сканер отвергает (позиция и текст ошибки совпали) | 189–220 на версию, 1–3 отвергнуты | 0 |
| Случайные склейки лексических фрагментов, 7 сидов в разных процессах | 320 000 (в них 11–35 тыс. отвергнутых сканером на сид) | 0 |
| Мутации реальных операторов PostgreSQL 16 | 20 000 (3 741 отвергнуто) | 0 |

Случайные входы нашли и заставили исправить: разбиение `{decinteger}{identifier}` по внутреннему подчёркиванию (`1_0$` — ошибка, а не число и `$`), границы текста в «at or near» (flex ставит NUL после текущего совпадения, и PostgreSQL печатает текст только до него). Отклонения libpg_query от сервера описаны в [docs/differences.md](docs/differences.md); в регрессионных тестах они не встречаются, в случайных входах — по 0–1 на сид.

Скорость: 1,64 мкс на оператор регрессионных тестов PostgreSQL 16, 47 МБ/с, 119 нс на токен, 0 аллокаций (`results/metrics.json`, `stage1.lexer.speed_pg16`). Сборка: самый тяжёлый пакет библиотеки (`internal/lex`) компилируется в 49 МБ, чистая сборка библиотеки 11 с (`build`).

Собственные тесты лексера в библиотеке: `internal/lex/lex_test.go`.
